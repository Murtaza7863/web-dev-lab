Forms and inputs

In your Java CLI app, Scanner reads what the user types. On the web, users type into input fields inside a form.

Basic form

Live example (won't do anything yet when you click — that's JavaScript later)
<form>
  <input type="text" placeholder="Description">
  <input type="number" placeholder="Amount">
  <input type="text" placeholder="Category">
  <button type="button">Add Expense</button>
</form>

Key pieces

<form> Groups inputs together. Like a dialog box for data entry.
<input> A text box. Self-closing — no </input> needed.
type="text" Regular text (description, category)
type="number" Numbers only (amount)
placeholder="..." Gray hint text shown when the box is empty
<button> A clickable button. Text goes between opening and closing tags.

Labels (optional but good practice)

Labels tell the user what each input is for:

<label for="desc">Description:</label>
<input id="desc" type="text">
       ^^^^^^^^^^^^^^^^ must match the label's for=""
Java comparison:
System.out.print("Enter description: ") → the <label>
String desc = sc.next() → the <input>
Choosing menu option 1 → clicking the <button> (once JS is wired up)
Why type="button"? Without it, a button inside a form tries to submit the form and reload the page. We use type="button" for now so nothing breaks before we add JavaScript.
